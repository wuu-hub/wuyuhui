# 伴生模块 P4 设想：分享 / 导出卡片

| 项目 | 内容 |
| --- | --- |
| 模块编号 | P4 |
| 模块名称 | 分享 / 导出卡片（学习卡片分享器） |
| 课程 | 移动互联网应用开发实战（1 学分） |
| 强制技术点 | Intent、FileProvider、位图 |
| 状态 | 里程碑 1 设计阶段 |

## 一、定位

主 App 回答「今天该复习哪些词」，伴生模块回答「我的学习状态怎么给别人看」。

它只做两件具体的事：

1. 把学习统计画成一张图片卡片，调起系统分享面板发出去；
2. 把词条与复习记录导出成 CSV 文件，同样通过分享面板发出去。

不做编辑、不做美化模板市场、不做社交，范围收得很窄，但每个环节都要真的跑通：图片要能在微信里打开，CSV 要能在 Excel 里正确显示中文。

## 二、满足「伴生模块最低标准」

| 标准 | 本模块如何满足 |
| --- | --- |
| 可独立启动或从主屏 / 系统入口触发 | 独立 APK，自带启动图标与桌面入口；同时在系统分享面板注册 `ACTION_SEND`（接收文本 / 图片）作为第二入口；主 App 统计页也有跳转按钮 |
| 能读写主 App 数据 | 通过主 App 暴露的只读 ContentProvider 查询词库列表、词条数量、复习记录；导出时按查询结果生成文件 |
| 有基本异常处理 | 无数据空态、主 App 未安装、FileProvider 配置异常、无可用分享目标四类场景均有明确提示 |
| 在 Git 中独立可追溯 | 独立 Gradle 模块目录 `companion/`，与主 App 同仓库，提交记录按模块前缀区分 |

## 三、独立运行方式

采用**独立 APK**方案：

- 独立 Gradle 模块 `companion`，`applicationId = com.wuyuhui.wordmemo.companion`；
- 与主 App 使用同一签名，安装后作为两个独立图标存在；
- 数据通过 `content://com.wuyuhui.wordmemo.provider/...` 读取，主 App 侧声明 `android:readPermission` 自定义权限，双方 `uses-permission` 对齐；
- 若跨进程权限联调成本过高，退化为同一 APK 内的独立 Activity（通过 Deep Link 从桌面直达），仍满足「独立可演示」。

## 五、技术实现要点

### 1. 位图生成

```
宽高固定 1080 × 1350 → Bitmap.createBitmap
Canvas 绘制：背景、标题、四个指标块、词库分布条形图、底部水印
统计数据来自 ContentProvider 查询结果
```

用原生 Canvas 而非截屏，原因是截屏受屏幕密度与状态栏影响，输出不稳定；Canvas 绘制结果在任何设备上一致。

### 2. FileProvider

```xml
<provider
    android:name="androidx.core.content.FileProvider"
    android:authorities="com.wuyuhui.wordmemo.companion.fileprovider"
    android:exported="false"
    android:grantUriPermissions="true">
    <meta-data
        android:name="android.support.FILE_PROVIDER_PATHS"
        android:resource="@xml/file_paths" />
</provider>
```

`file_paths.xml` 只暴露 `cache/` 与 `files/exports/` 两个子目录，不放行根目录，避免越权暴露内部数据。

### 3. 分享 Intent

```
Intent(ACTION_SEND).apply {
    type = "image/png"（或 "text/csv"）
    putExtra(EXTRA_STREAM, uri)
    addFlags(FLAG_GRANT_READ_URI_PERMISSION)
}
→ Intent.createChooser 后 startActivity
```

CSV 的 MIME 用 `text/csv`，部分邮件客户端识别为 `application/csv`，二者按目标应用能力选择。

### 4. 跨进程读数据

主 App 侧注册只读 Provider，只暴露查询，不开放 insert / update / delete：

| URI | 返回 |
| --- | --- |
| `.../libraries` | 词库 id、名称、词数 |
| `.../words` | 词条基础字段（不含复习内部状态以外的敏感项） |
| `.../stats` | 汇总：到期数、已学数、连续天数 |

## 六、验收演示脚本（3 分钟内的模块段落）

1. 桌面点开独立图标，首页显示主 App 数据摘要（证明跨进程读取成功）；
2. 点「生成卡片」，预览出现（证明位图生成）；
3. 点「分享」，系统分享面板弹出，选择微信发送给文件传输助手（证明 Intent + FileProvider）；
4. 回到 App 点「导出 CSV」，保存后在 Excel 打开，中文正常（证明编码与转义）；
5. 卸载主 App 再打开伴生模块，出现「未检测到主 App」提示而不崩溃（证明异常处理）。

## 七、风险

| 风险 | 预案 |
| --- | --- |
| 独立 APK 跨进程读取需自定义权限，配置繁琐易错 | 先把 Provider 用 `exported=true` + 只读接口在本机验证跑通，再收紧权限 |
| 部分 App 不认 `content://` 授权 | 分享前预检目标；对仅支持文件路径的目标退化为「先保存到相册再分享」 |
| Excel 打开 CSV 中文乱码 | 统一 UTF-8 BOM，并在导出后本地抽样打开验证，不只测纯英文数据 |
| 图片在深色背景下看不清 | 卡片固定浅色底，不跟随系统深色模式 |
