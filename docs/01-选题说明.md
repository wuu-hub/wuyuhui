## 一、题目名称

- 主 App：**单词记忆（WordMemo）**——基于艾宾浩斯遗忘曲线的单词复习应用
- 伴生模块：**学习卡片分享器（WordMemo Share）**——分享 / 导出卡片

## 二、一句话定位

主 App 把「背单词」这件事做成一条可计算的时间线：每个词条都有下一次该复习的时刻，App 每天只把到期的词推给用户，并按用户的实际回忆表现动态调整间隔。

伴生模块把这条时间线变成可传阅的东西：把学习统计渲染成一张图片卡片、把复习数据导出成 CSV，通过系统分享面板发到微信、邮件等任意 App。

## 三、选题理由

1. **算法是刚需，不是装饰。** 单词记忆的核心不是增删改查，而是「什么时候该复习哪个词」。艾宾浩斯遗忘曲线给出一套可验证的间隔调度规则，天然满足课程「必须有自定义业务逻辑模块」的要求，且算法可以脱离 UI 单独写单元测试。
2. **数据链路完整。** 词库导入 → 词条入库 → 复习事件记录 → 调度重算 → 统计展示，一条闭环把 Room、协程、ViewModel、WorkManager 全部串起来，不是拼凑的功能点。
3. **伴生模块有真实形态。** 分享不是演示用的假按钮：位图生成、FileProvider 授权、跨 App Intent 传递，每一步都有明确的失败模式，正好用来体现异常处理。
4. **和本人学习场景吻合。** 四级词汇与专业英语词条都需要长期重复记忆，项目做完可以直接自用。

## 四、对照「最低复杂度标准」逐条说明

课程要求主 App 必须同时满足以下 7 条，逐条说明如下。

### 1. ≥ 4 个界面，包含「列表 → 详情」的导航结构

**满足。** 规划 7 个界面：

| 序号 | 界面 | 职责 |
| --- | --- | --- |
| 1 | 今日（Dashboard） | 今日到期词数、连续学习天数、开始复习入口 |
| 2 | 词库列表（LibraryList） | 词库卡片列表，支持新建与导入 |
| 3 | 词库详情（LibraryDetail） | 该词库的词条列表，支持搜索与排序 |
| 4 | 词条详情（WordDetail） | 单词释义、复习历史、下次复习时间、手动作答记录 |
| 5 | 复习（Review） | 卡片式逐词复习，四档自评（忘记 / 模糊 / 想起 / 熟练） |
| 6 | 测试（Quiz） | 拼写题与选择题混合的测试模式 |
| 7 | 统计（Stats） | 学习量、正确率、复习分布图表 |

导航结构为「词库列表 → 词库详情 → 词条详情」，是标准的列表到详情；「今日 → 复习」「测试 → 结果」为并列二级流程。

### 2. 数据持久化：Room / DataStore / 文件存储，至少使用一种

**满足，且用两种。**
- **Room**：`WordLibrary`（词库）、`Word`（词条，含 `intervalIndex`、`nextReviewAt`、`easeFactor`、`lapses`）、`ReviewLog`（每次复习的时间与自评结果）三张表，带索引与外键。
- **DataStore（Preferences）**：每日新词上限、连续学习天数、上次复习日期等轻量设置。

### 3. 至少具备一项硬能力

**满足，选择「后台任务」。**
- 用 **WorkManager** 注册每日一次的周期任务：在设定时间扫描当天到期词条数量，若大于 0 则发一条复习提醒通知；同时承担逾期词条的重排。
- 权限降级完全落在这条能力上：用户关闭通知权限时，App 不崩溃、不空转，改为在首页顶部显示一条「今日 N 个词待复习」的横幅作为替代提醒，并在设置页给出一键跳转通知设置入口。

### 4. 异步与生命周期处理正确：协程 + ViewModel，避免内存泄漏与主线程阻塞

**满足，作为硬性编码约定。**
- 所有数据库读写走 `Dispatchers.IO` 的挂起函数，ViewModel 通过 `viewModelScope` 启动，界面只消费 `StateFlow` 暴露的 UI State。
- 复习调度计算放在 `Dispatchers.Default`，不占用主线程。
- Activity 与 ViewModel 之间不持有彼此引用；Compose 侧用 `collectAsStateWithLifecycle()`，避免后台仍在收集。

### 5. 权限申请与降级处理

**满足。** 本项目权限面很窄，正合适做干净的降级设计：

| 权限 | 用途 | 用户拒绝后的行为 |
| --- | --- | --- |
| `POST_NOTIFICATIONS`（Android 13+） | 每日复习提醒 | 不申请第二次，改为首页横幅提示；设置页保留手动开启入口；WorkManager 任务照常计算但不发通知 |
| 无外部存储权限 | 导入 / 导出走 SAF 与 FileProvider | 不涉及存储权限申请，从根上避免被拒 |

伴生模块的 FileProvider 属于组件级授权，运行期不需要用户授予任何权限，配置遗漏时降级为提示「当前无法分享，可先复制文本」。

### 6. 至少一个自定义业务逻辑模块

**满足，这是本项目的主线。**

调度模块 `ReviewScheduler` 不是增删改查：

- 维护 10 档基础间隔（5 分钟、30 分钟、12 小时、1 天、2 天、4 天、7 天、15 天、30 天、60 天）；
- 每次作答四档自评，按档位决定间隔前进、原地重复或回退；
- 每个词条维护难度因子 `easeFactor`（初始 2.5，下限 1.3），答错时下调、答对时小幅上调，影响后续间隔的放大倍数；
- 逾期词条不直接跳过，而是按逾期天数折算一个「补偿间隔」，避免长时间不学后队列一次性爆炸；
- 结果为纯函数：`(当前状态, 自评结果, 当前时间) -> 新状态`，可完全脱离数据库做单元测试。

此外统计模块提供正确率、连续天数、复习量分布的计算，也属于业务逻辑而非简单查询。

### 7. 加载态 / 空态 / 错误态 UI 完整

**满足。** 每类界面在规划阶段就定好三态：

| 场景 | 加载态 | 空态 | 错误态 |
| --- | --- | --- | --- |
| 词库列表 | 骨架占位 | 「还没有词库，导入一个或新建一个」+ 两个操作按钮 | 读取失败提示 + 重试 |
| 词库详情 | 列表骨架 | 「该词库暂无词条」 | 查询失败提示 + 重试 |
| 今日 | 数字占位 | 「今天没有要复习的词，去学新词」 | 计算失败提示 |
| 词语导入 | 进度条 | 文件为空提示 | 格式不合法：指出第几行有问题，不整批丢弃 |
| 测试 | 题量准备提示 | 「本词库可测词条不足，至少需要 4 个」 | 生成失败可重试 |

## 五、拟用技术点

### 主 App

| 分类 | 技术点 | 用途 |
| --- | --- | --- |
| UI | Jetpack Compose、Material 3 | 全部界面与主题 |
| 导航 | Navigation Compose | 列表到详情、复习与测试流程 |
| 持久化 | Room（含 DAO、Migration、索引） | 词库、词条、复习记录 |
| 持久化 | DataStore Preferences | 设置与连续天数 |
| 异步 | Kotlin 协程、Flow、StateFlow | 数据流与后台计算 |
| 架构 | ViewModel + UI State 单向数据流 | 与生命周期解耦 |
| 后台 | WorkManager（周期任务 + 约束） | 每日提醒与逾期重排 |
| 通知 | NotificationChannel + 运行时权限 | 复习提醒与降级 |
| 算法 | 自实现艾宾浩斯 / SM-2 变体调度 | 核心业务逻辑 |
| 文件 | SAF 文件选择（`ActivityResultContracts.OpenDocument`） | 词库导入 |
| 测试 | JUnit 单元测试 | 调度算法可复现验证 |

### 伴生模块

| 分类 | 技术点 | 用途 |
| --- | --- | --- |
| 组件通信 | Intent（`ACTION_SEND`、`FLAG_GRANT_READ_URI_PERMISSION`） | 调起系统分享面板 |
| 文件共享 | FileProvider + `content://` URI | 把图片 / CSV 授权给其他 App 读取 |
| 图形 | Bitmap + Canvas 绘制（或 Compose 离屏渲染） | 生成统计卡片图片 |
| 跨进程数据 | ContentProvider（主 App 暴露只读查询） | 独立 APK 读取主 App 数据 |
| 兼容 | `PackageManager.queryIntentActivities` 预检 | 无可用分享目标时降级提示 |

## 六、边界与不做的事

- 不做账号体系、不做云同步、不做付费与社交，范围锁定在本地学习闭环。
- 不做词库在线商店，词库来源是本地文件导入与内置示例词库。
- 不做发音评测，TTS 发音作为可选项，不进核心验收路径。
- 伴生模块不写主 App 数据，只读，避免双写冲突。

## 七、风险与预案

| 风险 | 预案 |
| --- | --- |
| 算法参数调不好，导致队列要么爆要么空 | 先用固定间隔序列跑通，再引入 `easeFactor`；算法层写单元测试锁定行为 |
| WorkManager 在国产 ROM 上被清理 | 提醒作为增强而非唯一入口，首页横幅始终可用 |
| FileProvider 配置错误导致分享失败 | 单独写一个最小验证页，先跑通图片分享再接业务 |
| 独立 APK 读主 App 数据需要跨进程 | 用 ContentProvider 只读接口；若权限复杂度过高，退化为「同 APK 内独立 Activity + 独立启动入口」，仍满足独立演示 |
