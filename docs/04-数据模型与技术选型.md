# 数据模型与技术选型

> 对应里程碑 2（数据模型、技术选型）与里程碑 3（骨架与导航）。本文记录表结构、算法规则、依赖版本与本次实测结论。

## 一、数据模型

### 1. 表结构

三张表，词库为父表，词条与复习记录为子表，删除词库时级联删除。

#### `word_libraries`（词库）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK 自增 | 主键 |
| name | TEXT | 词库名称 |
| description | TEXT | 描述，可空串 |
| source | TEXT | `BUILT_IN` / `IMPORTED` / `MANUAL` |
| createdAt | INTEGER | 创建时间，epoch millis |

#### `words`（词条）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK 自增 | 主键 |
| libraryId | INTEGER FK | 指向 `word_libraries.id`，`ON DELETE CASCADE` |
| spelling | TEXT | 拼写 |
| meaning | TEXT | 释义 |
| example | TEXT NULL | 例句 |
| phonetic | TEXT NULL | 音标 |
| intervalIndex | INTEGER | 当前间隔档位 0～9 |
| nextReviewAt | INTEGER | 下次复习时刻，epoch millis |
| easeFactor | REAL | 难度因子，初始 2.5 |
| lapses | INTEGER | 忘记次数 |
| isStarred | INTEGER | 是否标星 |
| createdAt | INTEGER | 创建时间 |

索引：
- `libraryId`：按词库查询词条；
- `nextReviewAt`：按到期时间取队列，这是「今日」页的核心查询；
- `(libraryId, spelling)` 唯一索引：同一词库内不允许重复单词，导入去重直接由约束兜底。

#### `review_logs`（复习记录）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK 自增 | 主键 |
| wordId | INTEGER FK | 指向 `words.id`，级联删除 |
| reviewedAt | INTEGER | 复习时刻 |
| grade | TEXT | 自评档位枚举名 |
| previousIntervalIndex / newIntervalIndex | INTEGER | 复习前后的档位，用于回放算法行为 |
| previousEaseFactor / newEaseFactor | REAL | 复习前后的难度因子 |
| elapsedMs | INTEGER | 本次作答耗时 |

索引：`wordId`、`reviewedAt`。

复习记录采用**只追加**设计，不更新不删除。这样算法每一步调整都可追溯，答辩时能拿出「某个词为什么被排到明天」的直接证据。

### 2. 关系

```
word_libraries (1) ──< (N) words (1) ──< (N) review_logs
```

### 3. 为什么把调度状态存在词条上

若每次复习都从历史记录重算状态，需要扫描该词条全部日志，随学习时长增长会变慢；把 `intervalIndex`、`easeFactor`、`lapses`、`nextReviewAt` 冗余在词条行上，读取是 O(1)，日志只承担追溯职责。两者的一致性由仓库层 `submitReview` 保证：一次调用里同时更新词条与写入日志。

## 二、调度算法

### 1. 基础间隔（10 档）

| 档位 | 间隔 |
| --- | --- |
| 0 | 5 分钟 |
| 1 | 30 分钟 |
| 2 | 12 小时 |
| 3 | 1 天 |
| 4 | 2 天 |
| 5 | 4 天 |
| 6 | 7 天 |
| 7 | 15 天 |
| 8 | 30 天 |
| 9 | 60 天 |

前 3 档是分钟 / 小时级，用于当天内的短时巩固；第 3 档起进入天级。

### 2. 四档自评规则

| 自评 | 档位变化 | 难度因子变化 | 忘记次数 |
| --- | --- | --- | --- |
| 忘记 | 回到 0 档 | −0.20 | +1 |
| 模糊 | 原地不动 | −0.10 | 不变 |
| 想起 | 前进 1 档 | 不变 | 不变 |
| 熟练 | 前进 2 档 | +0.15 | 不变 |

难度因子被限制在 `[1.3, 3.0]`，档位限制在 `[0, 9]`。

### 3. 实际间隔计算

```
基础间隔 = IntervalTable[newIndex]
若 newIndex ≤ 2：实际间隔 = 基础间隔              （低档不放大，避免 5 分钟 × 2.5 变成 12.5 分钟）
否则：       实际间隔 = 基础间隔 × 难度因子
```

### 4. 逾期补偿

```
逾期比例 r = (当前时间 − 原定复习时间) / 基础间隔
补偿系数 = min(1 + r, 2.0)
最终延迟 = 实际间隔 × 补偿系数
```

未逾期时系数为 1，不改变正常节奏；逾期越久间隔越长，但封顶 2 倍，避免长期中断后一次性堆出巨量到期词。

### 5. 纯函数设计

`EbbinghausScheduler.apply(state, grade, now)` 只依赖入参与当前时间，不读数据库、不碰 Android API，因此可以直接用 JVM 单元测试验证。

## 三、技术选型

| 项目 | 版本 | 选择理由 |
| --- | --- | --- |
| Kotlin | 2.2.10 | 课程要求原生 Kotlin，与 AS 2026.1 内置工具链一致 |
| AGP | 9.3.0 | 与本机 Android Studio 2026.1 配套，AGP 9 起内置 Kotlin 支持 |
| Gradle | 9.5.0 | 与 AGP 9.3 兼容，本机已有发行包 |
| compileSdk / targetSdk | 37 | 本机仅安装 android-37 平台 |
| minSdk | 26 | 覆盖课程演示机型，同时可直接使用 `java.time` |
| UI | Jetpack Compose + Material 3（BOM 2026.09.00） | 声明式 UI，列表与详情复用组件成本低 |
| 导航 | Navigation Compose 2.10.2 | 类型安全的路由参数，Long 主键直接传 |
| 持久化 | Room 2.8.5（KSP 2.2.10-2.0.2） | 编译期校验 SQL，支持 Flow 与协程 |
| 异步 | 协程 + StateFlow + ViewModel | 数据流单向传递，界面不持有数据库引用 |
| 测试 | JUnit 4.13.2 | 纯 JVM 跑算法测试，不依赖模拟器 |

### AGP 9 的两个约定（踩坑记录）

1. **不能应用 `org.jetbrains.kotlin.android`**：AGP 9 已内置 Kotlin 支持，重复应用会报 `Cannot add extension with name 'kotlin'`。
2. **KSP 需要放开源码集限制**：内置 Kotlin 默认禁止 KSP 通过 `kotlin.sourceSets` 注入生成目录，须在 `gradle.properties` 设 `android.disallowKotlinSourceSets=false`。
3. 工程路径含中文时 AGP 默认拒绝构建，本机已设 `android.overridePathCheck=true`，实测可正常编译与打包。

| 项目 | 命令 | 结果 |

### 已知环境限制

本机只有 JDK 25（Android Studio 自带运行时），Gradle 9.5 的测试 worker 在该 JDK 下无法启动（`ClassNotFoundException: worker.org.gradle.process.internal.worker.GradleWorkerMain`），`gradlew :app:testDebugUnitTest` 会失败；同一现象在纯 ASCII 路径下复现，与工程路径无关。当前改用 JUnitCore 直接加载编译产物执行测试，结果可靠。后续在 Android Studio 内点测试或在 JDK 17/21 环境下运行 `gradlew test` 可恢复正常。
