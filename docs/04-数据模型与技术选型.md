# 数据模型与技术选型

> 记录实际表结构、调度规则、依赖版本与实测结论。所有内容与 `com.example.wordapp` 当前代码一致。

## 一、数据模型

### 1. 表结构

单表 `words`，一个词一行，复习状态直接冗余在行上。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` | INTEGER PRIMARY KEY AUTOINCREMENT | 主键 |
| `word` | TEXT NOT NULL | 拼写 |
| `meaning` | TEXT NOT NULL | 释义 |
| `example` | TEXT NOT NULL DEFAULT '' | 例句 |
| `stage` | INTEGER NOT NULL DEFAULT 0 | 艾宾浩斯阶段 0～5 |
| `learned` | INTEGER NOT NULL DEFAULT 0 | 是否学过（0 未学 / 1 已学） |
| `review_count` | INTEGER NOT NULL DEFAULT 0 | 累计复习次数 |
| `correct_count` | INTEGER NOT NULL DEFAULT 0 | 累计答对次数 |
| `created_at` | INTEGER NOT NULL | 创建时间，epoch millis |
| `last_review_at` | INTEGER NOT NULL DEFAULT 0 | 上次复习时刻 |
| `next_review_at` | INTEGER NOT NULL DEFAULT 0 | 下次复习时刻，到期队列按它排序 |

### 2. 索引

| 索引 | 字段 | 用途 |
| --- | --- | --- |
| `idx_word`（UNIQUE） | `word` | 导入去重，重复词由约束直接跳过 |
| `idx_due` | `(learned, next_review_at)` | 首页「今日待复习」与复习队列的主查询 |
| `idx_stage` | `stage` | 测试优先抽未掌握词 |

### 3. 迁移策略

数据库版本 1 → 2：

- 版本 2 新增 `idx_due`、`idx_stage` 两个索引；
- `onUpgrade` 只做增量补索引，**不再 DROP 表重建**。早期写法是「删表重建」，升一次版本就把用户背过的词全清空，这次一并修掉；
- 实测：从 v1 升级到 v2 后，20 条词条一条不少，索引全部建立。

### 4. 为什么用单表

课程场景词库规模是个位数到几百条，拆词库表与复习日志表会带来 JOIN 与额外一致性维护。把 `stage`、`review_count`、`next_review_at` 直接放在词条行上，到期查询与统计都是单表扫描，索引足够覆盖。

## 二、调度算法

### 1. 六档基础间隔

| 阶段 | 间隔 |
| --- | --- |
| 0 | 1 天 |
| 1 | 2 天 |
| 2 | 4 天 |
| 3 | 7 天 |
| 4 | 15 天 |
| 5 | 30 天（视为已掌握） |

### 2. 作答规则

| 作答 | 阶段变化 | 下次复习 |
| --- | --- | --- |
| 认识 | `min(stage + 1, 5)` | `now + 新阶段间隔` |
| 不认识 | `max(stage - 1, 0)` | `now + 10 分钟`（当天再背一次） |

`schedule(remember, stage, now)` 是纯函数，只依赖入参，不读数据库、不碰 Android API。

### 3. 队列生成规则

```
本次队列 = 到期词（learned=1 且 next_review_at ≤ now，按到期时间升序，最多 30 条）
         + 新词（learned=0，按创建时间升序，最多 10 条）
```

- **限流**：单次最多 30 条到期词，防止长时间不打开后一次性堆积；
- **错词重排**：本轮答错的词，更新后追加到队列末尾再出现一次，同一词只追加一次（`retried` 集合），避免无限循环；
- **断点续答**：队列 id、当前下标、记得次数、已重试词写进 SharedPreferences，24 小时内重开可接着答；完成或会话过期即清除。

### 4. 测试抽题规则

```
优先从 stage < 5 的词中随机抽取
不足时用全库随机补齐，并按 id 去重
干扰项从其他词的释义中随机取 3 个，不足时用「（干扰项 N）」占位
```

测试结果只影响当次得分展示，不写回复习调度，避免与复习流程互相干扰。

## 三、技术选型

| 项目 | 版本 / 选择 | 理由 |
| --- | --- | --- |
| AGP | 9.3.0 | 与本机 Android Studio 配套；AGP 9 内置 Kotlin 支持 |
| Gradle | 9.5 | 与 AGP 9.3 兼容 |
| Kotlin | 随 AGP 内置（2.2.x） | 无需单独应用 `org.jetbrains.kotlin.android` |
| compileSdk / targetSdk | 37 | 本机安装的 SDK 平台 |
| minSdk | 24 | 覆盖演示机型，同时可用 `FileProvider` 与 SAF |
| UI | XML + ViewBinding + Material Components | 便于课程答辩时逐个布局讲解 |
| 页面载体 | Activity | 4 个页面职责清晰，不引入导航框架 |
| 持久化 | SQLiteOpenHelper 手写 SQL | 表结构简单，手写 SQL 便于说明索引与迁移 |
| 数据访问 | 单例 `WordRepository` | 界面不直接持有数据库 |
| 网络 | HttpURLConnection + `org.json` | 只发一个 GET，无需 OkHttp / Gson |
| 后台 | AlarmManager + BroadcastReceiver | 每日一次提醒，不需要 WorkManager |
| 分享 | FileProvider + Intent | P4 强制技术点 |
| 图形 | Bitmap + Canvas | P4 强制技术点 |

### AGP 9 的两个约定（踩坑记录）

1. **不能应用 `org.jetbrains.kotlin.android`**：AGP 9 已内置 Kotlin 支持，重复应用会报 `Cannot add extension with name 'kotlin'`。
2. 工程路径含中文时需在 `gradle.properties` 设置 `android.overridePathCheck=true`，否则构建被拒。

## 四、实测结论

| 项目 | 命令 / 操作 | 结果 |
| --- | --- | --- |
| Debug 编译打包 | `gradlew :app:assembleDebug` | 成功，约 20～30 秒，APK 约 5.9 MB |
| 数据库升级保留数据 | v1 库装入 v2 APK | 20 条词条全部保留，`idx_due`、`idx_stage` 建立成功 |
| 错词当场重排 | 3 个到期词，第 1 个答"不认识" | 进度从 `1 / 3` 变为 `2 / 4`，队尾再次出现该词，阶段由第 2 轮降为第 1 轮 |
| 复习断点续答 | 答 1 个后按 Home，杀进程重开 | 直接显示 `2 / 7`，从下一词继续 |
| 空态文案 | 全部词推向未来后进复习页 | 显示「今天的复习都完成了，明天再来巩固吧。」 |
| 联网查词成功 | 输入 beneficial | 提示已加入词库，总词数 20 → 21，释义含音标 |
| 联网查词失败 | 输入 zzzzq | 提示「词典里查不到」，词数保持 21，无脏数据 |

以上均在 MuMu 模拟器（Android 12，1600×900）上用 adb 实际操作验证，非仅静态检查。

## 五、已知限制

1. **未引入 ViewModel 与协程**：数据库读写目前在主线程、通过单例仓库直读；课程要求协程 + ViewModel，这一项需要补。
2. **未写单元测试**：`EbbinghausScheduler` 已是纯函数，具备直接单测的条件，但测试类尚未落地。
3. **本机 JDK 25 下 `gradlew test` 无法启动测试 worker**（`ClassNotFoundException: GradleWorkerMain`），与工程路径无关；后续需 JDK 17/21 环境或在 Android Studio 内运行。
4. **单词本无详情页**：列表点进去的详情页尚未实现。
